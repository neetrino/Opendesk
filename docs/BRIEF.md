# Техническое задание — OpenDesk

> MVP: публичная Kanban-доска для обсуждений без регистрации.

---

## Описание

OpenDesk — минимальный task / discussion board для команды проекта. Одна общая публичная доска доступна только по персональному invite-токену: человек открывает ссылку, указывает имя и сразу попадает на доску. Без регистрации, email и паролей.

Цель MVP — быстро открывать вопросы, двигать карточки по стадиям и видеть ответы / обсуждения с указанием автора.

## Целевая аудитория

Участники текущего проекта (команда, стейкхолдеры, внешние консультанты), которым нужно обсуждать вопросы без онбординга в отдельный аккаунт.

**Основные сценарии:**
1. Организатор создаёт доску и рассылает уникальные invite-ссылки.
2. Участник открывает ссылку, вводит имя, работает на доске.
3. Участник создаёт карточку (вопрос или задачу), двигает по колонкам, пишет ответы в треде.

## Основные функции (приоритеты)

1. **Доска + уникальные invite-токены** — приоритет: высокий  
   Создание доски, генерация персональных invite-ссылок, вход по токену + имя (cookie/session без классической auth).

2. **Kanban 4 колонки** — приоритет: высокий  
   Стадии: Новый вопрос / обсуждение → В процессе → Ответ дан → Завершён. Любой участник доски может перемещать карточки.

3. **Два типа карточек** — приоритет: высокий  
   `question` и `task`, визуально различимы.

4. **Карточка: описание + тред** — приоритет: высокий  
   Заголовок, описание, автор; внутри — комментарии / ответы с именем автора и хронологией.

5. **Минимальный UI** — приоритет: высокий  
   Светлый минималистичный modern / creative дизайн, адаптив desktop + mobile.

### Вне MVP (не делать сейчас)

- Регистрация / OAuth / роли ADMIN vs USER
- Несколько досок на пользователя, workspace, биллинг
- Real-time WebSocket / live cursors
- Файлы, вложения, уведомления email
- Поиск, фильтры, аналитика, тёмная тема
- i18n

## Stack (решение)

- **Вариант A** — fullstack Next.js на Vercel (рекомендуется для MVP)
- NestJS / отдельный backend — не нужен

## Дизайн

- Figma: нет (design-from-brief)
- UI: светлый минимализм, modern; без тяжёлого UI-kit-оверкилла
- Рекомендация: Tailwind + лёгкие собственные компоненты (shadcn опционально)

## Интеграции

- [ ] Платёжная система — не нужно
- [ ] Email — не нужно
- [ ] Классическая аутентификация (Auth.js / Clerk) — не нужно
- [ ] Файловое хранилище (R2) — не нужно
- [ ] Внешние API — не нужно

**Нужно:** PostgreSQL (Neon) + Prisma.

## Язык контента

- Интерфейс: русский
- i18n: нет

## Ограничения

- Срок: как можно быстрее (MVP)
- Размер проекта: **A** (максимум B) — целевой **A**
- Бюджет: минимальный (без лишних платных сервисов)
- Технические: Next.js обязательно; без регистрации

## Дополнительно

- Invite: каждое приглашение уникально; участник привязывается к токену через имя при первом входе.
- Одна доска на инвайт-контекст (MVP: модель «создал доску → шаришь инвайты»).
- Имя участника хранится в cookie / signed session после claim invite — чтобы авторство карточек и комментариев было стабильным в рамках браузера.
